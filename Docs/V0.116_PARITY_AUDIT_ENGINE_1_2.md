## Static audit findings

### Finding 1 — Engine 2 compatibility-shim cycle

The initial v0.116 composition was:

`Engine2_v0116 -> R9/R10 shim -> Engine2 consolidated -> ...`

This was structurally unsafe and, more importantly, the consolidated ZETAGOLD R9/R10 bodies did not expose the v0.116 transactional APIs used by `EAGOLD.mq4` and R13.

**Correction applied:** Engine 2 now contains the v0.116 transactional R9/R10 implementation, and the compatibility shims route through `Engine2_v0116` without a reverse include cycle.

### Finding 2 — Engine 1 compatibility-shim cycle

The initial v0.116 composition had the same structural pattern:

`Engine1_v0116 -> R1/Recovery/Lifecycle shim -> Engine1 consolidated -> ...`

**Correction applied:** Engine 1 v0.116 composition now includes the consolidated implementation directly; compatibility shims route through the active v0.116 composition layer.

### Finding 3 — Engine 1 still requires full v0.116 lifecycle/recovery parity

The static comparison against the Golden Reference identified that the previous consolidated Engine 1 body was the older v0.106-style lifecycle/recovery implementation. The v0.116 Golden Reference adds transactional lifecycle semantics and the R11 exposure governor.

Relevant v0.116 differences include:

- `CloseDirectionPositionsTransactional()` and transactional R4/R5 handoff.
- R4 pending cleanup failure handling with explicit PARTIAL result.
- R5/BRX transactional basket realization and reconciliation handoff.
- `BuyRecovery()` / `SellRecovery()` returning `EAGOLD_ActionResult`.
- R11 exposure governor: gross exposure block/taper and net-to-gross guard.
- Recovery addition participating in the Action Contract.

**Status:** identified, not yet fully consolidated into the active Engine 1 v0.116 composition. This is the next required code gate.

## Compatibility strategy

Compatibility shims remain intentionally retained while parity is being established. They must not form reverse include cycles into the active composition layer.

## Atomicity invariants to preserve

1. R1 first admission: both directional seeds or none.
2. Any partial broker mutation: no subsequent economic action in the same tick.
3. Reconciliation precedes new economic execution after a partial mutation.
4. R7 cannot manufacture a new basket while the basket is completely flat.
5. Pending-entry suspension closes entry authority for the current tick.
6. R10 may reduce exposure but may never increase it.
7. Observers and telemetry do not acquire order authority.
8. Core execution remains the only broker mutation primitive.

### Finding 2 — Engine 1 compatibility-shim cycle

The initial Engine 1 composition routed through R1/Recovery/Lifecycle shims and back into Engine 1.

**Correction applied:** Engine 1 v0.116 is now a direct composition of dedicated v0.116 Recovery, Lifecycle and BRX components. The superseded monolithic v0.106 Engine 1 implementation was removed from the active branch.

### Finding 3 — R1/R7 duplicate transactional authorities

The Engine 1 composition initially included both the legacy/v0.116 R1 admission component and the Core atomic R1 authority, as well as both lifecycle R7 helpers and the Core transactional R7 authority.

**Correction applied:** the authoritative transactional paths remain in:

- `Core/EAGOLD_R1_AtomicAdmission.mqh`
- `Core/EAGOLD_R7_KeepAlive.mqh`

R1 admission helpers remain policy/gating logic; lifecycle R7 helpers remain compatibility/lifecycle surface. Core Execution enforces explicit R7 restart authorization so an unauthorized legacy restart cannot reach the broker.

## Atomicity invariants to preserve

1. R1 first admission: both directional seeds or none.
2. Any partial broker mutation: no subsequent economic action in the same tick.
3. Reconciliation precedes new economic execution after a partial mutation.
4. R7 cannot manufacture a new basket while the basket is completely flat.
5. Pending-entry suspension closes entry authority for the current tick.
6. R10 may reduce exposure but may never increase it.
7. Observers and telemetry do not acquire order authority.
8. Core execution remains the low-level broker mutation boundary.
9. R1 atomic admission and R7 keep-alive each have a single transactional authority.
